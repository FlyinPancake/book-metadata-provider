# v1 Updates

This is a working document.

## Changes to the API

## Backwards Compatibility

The API should remain backwards compatible with the v0.1.0 API, so the providers serving v0.1.0 can
be used by a client that implements the v1 API.

Some fields may be marked as deprecated for v1 but they cannot be dropped.

## Reference implementation

There wasn't a v0.1.0 reference implementation, but there needs to be one for v1. It should live in
this repository (either Python or TypeScript, make it easy to read and understand)

## Client libraries

For v1, i'd like to implement it here as a reference library implementation. This won't stop ABS to
implement their own client, it will just make it easier for other to adpot the spec. Additional
languages (Java / Kotlin for Grimmory, Python for shelfmark) could be added. These implementations
could be based on OpenAPI generators, but the fallback lines should be implemented manually.

## New features

### Separation of Audiobooks and Books

The original spec did not separate audiobooks and books, but this is a major change for v1. v1
should make it possible to a provider to tell if a book is an audiobook or a book. For backwards
compatibility, there should be an unknown type as the default.

### Field level documentation

Each field should be documented with a description and example values, not just with a type. This
helps developers understand how the values of each field are going to be used

### Multiple authors and narrators

Multiple authors and narrators should be supported via a list of authors and narrators.

### Ratings

Ratings should be supported.

### Grouping

If there are multiple versions of a book, they should be grouped together. This could be done via a
group ID.
